== architect
RUN one option below
  at architect: a branch you pick - take one option below, then state next
  options:
    state record architect.discuss - on to discuss
    state record architect.enough - on to architect/researchers
    state record architect.research - on to architect/research, which spawns a researcher in the foreground
    state record architect.ticket - on to ticket
  fuel: low
  Researchers: 0 of 10 used, 10 left
  Discussion questions: 0 of 50 used, 50 left
Discuss: this round's design questions one at a time, each through `state ask` and answered before the next, never two at once. First send the Explain message: the context, and pseudo-code or a diagram; then the picker question, your recommendation first, in the same turn, for each question. Once the round's last question is answered, record `discuss.asked`, back to the discussion's pick. There `research` spawns a researcher for any fact an answer opens, and `enough`, when nothing is open, waits for every researcher's hand-back. At either Fuel budget's end, asked whether to go on: yes is `extend <why>`, no is `enough`.
Gather: spawn a researcher per open fact group, in the background or not as its option says, each prompted per the researcher skill's `## Callers`; the hooks record each spawn and hand-back. Each researcher's task: Research the open fact group your prompt names, as the researcher skill says.
Ticket: write the design so far into the ticket, or edit it, at any point and as often as the design changes: the skill's `references/issue.md` sections from a quoted heredoc (`<<'EOF'`), into the ticket the request named (`gh issue edit <number> --repo <owner>/<repo> --body-file -`), else a new one (`gh issue create --repo <owner>/<repo>`), or a Linear issue when the request names Linear; `gh issue comment` adds to it. Then record `ticket.written <url>`, back to the discussion's pick. The ticket is optional: `enough` ends the run with or without one.
